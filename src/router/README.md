# ルーティング

## 基本

ほとんどのウェブサイトはルーティングによって動作します。Routerは「このURLが与えられたとき、
ページへ何を表示するべきか」という問いに答えます。

URLは複数の部分で構成されます。たとえば
`https://my-cool-blog.com/blog/search?q=Search#results` は次の要素から成ります。

- _スキーム_：`https`
- _ドメイン_：`my-cool-blog.com`
- **パス**：`/blog/search`
- **クエリ**（または**検索文字列**）：`?q=Search`
- _ハッシュ_：`#results`

Leptos Routerはパスとクエリ（`/blog/search?q=Search`）を扱います。このURLの一部に
対して、アプリケーションはページへ何をレンダリングすべきでしょうか。

## 基本思想

ほとんどの場合、ページへ表示する内容はパスによって決まるべきです。多くの
アプリケーションでは、利用者から見たアプリケーション状態の大きな変化がURLへ反映される
べきです。URLをコピーして別のタブで開けば、ほぼ同じ場所が表示される必要があります。

この意味で、Routerはアプリケーションのグローバル状態管理の中心です。何よりも、ページへ
表示する内容を決定します。

Routerは現在のlocationを特定のコンポーネントへ対応付け、この処理の大部分を行います。
