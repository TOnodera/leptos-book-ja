# 幕間：リアクティビティと関数

コアコントリビューターのひとりが最近、私にこう言いました。「Leptosを使い始めるまで、
こんなに頻繁にクロージャを使ったことはなかった」。その通りです。クロージャはあらゆる
Leptosアプリケーションの中心にあります。ときには少し滑稽に見えるほどです。

```rust
// シグナルは値を保持し、更新できる
let (count, set_count) = signal(0);

// 派生シグナルは、ほかのシグナルへアクセスする関数
let double_count = move || count.get() * 2;
let count_is_odd = move || count.get() & 1 == 1;
let text = move || if count_is_odd() {
    "odd"
} else {
    "even"
};

// エフェクトは依存するシグナルを自動的に追跡し、
// それらが変化すると再実行される
Effect::new(move |_| {
    logging::log!("text = {}", text());
});

view! {
    <p>{move || text().to_uppercase()}</p>
}
```

どこもかしこもクロージャだらけです！

しかし、なぜでしょうか。

## 関数とUIフレームワーク

関数はすべてのUIフレームワークの中心にあります。これは理にかなっています。
ユーザーインターフェイスの作成は、基本的に2つの段階へ分かれるからです。

1. 初回レンダリング
2. 更新

ウェブフレームワークは何らかの初回レンダリングを行った後、制御をブラウザへ戻します。
マウスクリックのようなイベントが発生したり、HTTPリクエストのような非同期タスクが完了したり
すると、ブラウザがフレームワークを再び起動して何かを更新させます。フレームワークは
ユーザーインターフェイスを更新するコードを実行し、ブラウザに再び起こされるまで休止します。

ここで重要なのは「何らかのコードを実行する」という部分です。Rustでもほかのプログラミング
言語でも、任意の時点でコードを実行する自然な方法は関数を呼び出すことです。実際、すべての
UIフレームワークは、何らかの関数を繰り返し再実行する仕組みに基づいています。

1. React、Yew、Dioxusなどの仮想DOM（VDOM）フレームワークは、コンポーネントまたはrender関数を繰り返し実行し、以前の結果と比較してDOMを修正できる仮想DOMツリーを生成します。
2. AngularやSvelteなどのコンパイル型フレームワークは、コンポーネントテンプレートを「作成」関数と「更新」関数へ分割し、コンポーネントの状態変化を検出すると更新関数を再実行します。
3. SolidJS、Sycamore、Leptosなどのきめ細かなリアクティブフレームワークでは、再実行される関数を_利用者自身_が定義します。

すべてのコンポーネントが行っているのは、まさにこのことです。

いつもの `<SimpleCounter/>` の例を、最も単純な形で見てみましょう。

```rust
#[component]
pub fn SimpleCounter() -> impl IntoView {
    let (value, set_value) = signal(0);

    let increment = move |_| *set_value.write() += 1;

    view! {
        <button on:click=increment>
            {value}
        </button>
    }
}
```

`SimpleCounter` 関数自体は一度だけ実行され、`value` シグナルも一度だけ作成されます。
フレームワークは `increment` 関数をイベントリスナーとしてブラウザへ渡します。ボタンを
クリックするとブラウザが `increment` を呼び出し、`set_value` を通じて `value` を更新します。
すると、ビュー内の `{value}` が表すひとつのテキストノードが更新されます。

関数はリアクティビティの鍵です。変化に応じてアプリケーション内の可能な限り小さな単位を
再実行する能力を、フレームワークへ与えます。

したがって、次の2点を覚えておいてください。

1. コンポーネント関数はrender関数ではなく、セットアップ関数です。一度しか実行されません。
2. ビューテンプレート内の値をリアクティブにするには、リアクティブな関数でなければなりません。つまり、シグナルか、シグナルをキャプチャして読み取るクロージャです。

```admonish note
これは実際、Leptosのstable版とnightly版の主な違いです。ご存じかもしれませんが、nightly
コンパイラと `nightly` featureを使うと、シグナルを関数として直接呼び出せます。つまり
`value.get()` の代わりに `value()` と記述できます。

しかし、これは単なる糖衣構文ではありません。「リアクティブなものは関数である」という、
非常に一貫した意味モデルを実現します。シグナルには関数を呼び出すことでアクセスします。
「引数としてシグナルを受け取りたい」場合は、`impl Fn() -> T` を満たすものなら何でも
受け取れます。この関数ベースのインターフェイスは、シグナル、メモ、派生シグナルを区別
しません。どれも関数として呼び出すことでアクセスできます。

残念ながら、シグナルのような任意の構造体へ `Fn` トレイトを実装するにはnightly版Rustが
必要です。この機能は長らく停滞しており、近いうちに変更（または安定化）される可能性は
低そうです。さまざまな理由からnightly版を避ける人も多いため、ドキュメントなどの
デフォルトは徐々にstable版へ移してきました。その結果、「シグナルは関数である」という
単純なメンタルモデルは、残念ながら少しわかりにくくなっています。
```
