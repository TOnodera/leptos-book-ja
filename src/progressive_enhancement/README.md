# プログレッシブエンハンスメント（とグレースフルデグラデーション）

私はボストン周辺で15年ほど車を運転しています。ボストンをご存じない方のために言っておくと、マサチューセッツ州には世界でも特に攻撃的な運転手（そして歩行者！）がいます。そこで私は「防衛運転」と呼ばれることのある方法を身につけました。交差点でこちらに優先権があっても誰かが目の前へ急に割り込むと想定し、歩行者がいつ道路へ飛び出してもよいよう備え、それに応じて運転するのです。

「プログレッシブエンハンスメント」は、Webデザインにおける「防衛運転」です。厳密には、それは「グレースフルデグラデーション」でしょう。ただし、この2つは同じコインの表裏、あるいは同じ過程を別の方向から見たものです。

この文脈での**プログレッシブエンハンスメント**とは、ページを訪れるどのユーザーにも動く単純なHTMLサイトまたはアプリケーションから始め、追加機能を層として段階的に強化していくことです。スタイルにはCSS、対話性にはJavaScript、Rustによる対話性にはWebAssemblyを使い、利用可能で必要なら特定のWeb APIを使って体験を豊かにします。

**グレースフルデグラデーション**とは、その強化の積み重ねの一部が利用_できない_とき、障害を穏やかに処理することです。ユーザーがアプリで遭遇しうる問題には、次のようなものがあります。

- ブラウザを更新する必要があり、WebAssemblyに対応していない。
- ブラウザの更新が新しいOSバージョンに限定され、そのOSを端末へインストールできないため、WebAssemblyに対応できない。（Apple、あなたのことですよ。）
- セキュリティまたはプライバシー上の理由でWASMを無効にしている。
- セキュリティまたはプライバシー上の理由でJavaScriptを無効にしている。
- 端末がJavaScriptに対応していない（たとえば、一部のアクセシビリティ端末はHTMLの閲覧だけに対応しています）。
- 外へ出てWi-Fiが切れ、JavaScript（またはWASM）が端末に届かなかった。
- 最初のページを読み込んだ後に地下鉄へ乗り、その後のページ遷移でデータを読み込めない。
- ……などです。

このうち1つが当てはまるとき、アプリはどの程度動き続けるでしょうか？ 2つなら？ 3つなら？

答えが「95%……なら90%……それなら75%」という具合なら、グレースフルデグラデーションができています。「すべてが正しく動かなければ空白画面になる」なら、それは……予定外の急速分解です。

**グレースフルデグラデーションはWASMアプリで特に重要です。** ブラウザで動く4つの言語（HTML、CSS、JS、WASM）のうち、WASMは最も新しく、対応していない可能性が最も高いからです。

幸い、役立つ道具があります。

## 防衛的な設計

アプリをより穏やかに縮退させるのに役立つ実践方法がいくつかあります。

1. **サーバーサイドレンダリング。** SSRがなければ、JSとWASMの両方を読み込まない限りアプリはまったく動きません。場合によっては適切でしょう（ログインで保護された社内アプリなど）が、単に壊れているだけの場合もあります。
2. **ネイティブHTML要素。** 追加コードなしで望む動作をするHTML要素を使います。ナビゲーション（ページ内のハッシュへの移動を含む）には `<a>`、アコーディオンには `<details>`、URLへ情報を保持するには `<form>` などです。
3. **URL駆動の状態。** グローバル状態をURL（ルートパラメーターまたはクエリ文字列の一部）へ多く保存するほど、サーバーレンダリング中に生成し、`<a>` や `<form>` で更新できるページ部分が増えます。つまり、ナビゲーションだけでなく状態変更もJS／WASMなしで動作できます。
4. **[`SsrMode::PartiallyBlocked` または `SsrMode::InOrder`](https://docs.rs/leptos_router/latest/leptos_router/enum.SsrMode.html)。** 順不同のストリーミングには少量のインラインJSが必要で、1）レスポンスの途中で接続が切れた場合、または2）クライアント端末がJSに対応していない場合に失敗することがあります。非同期レンダリングなら完全なHTMLページを得られますが、すべてのリソースが読み込まれた後だけです。順序どおりのストリーミングは、ページの断片を上から順に、より早く表示し始めます。「部分的にブロックする」SSRは順不同のストリーミングを基礎に、ブロッキングリソースを読み取る `<Suspense/>` 断片をサーバー上で置き換えます。`O(n)` の文字列置換処理により初期レスポンス時間がわずかに増える代わりに、より完全な初期HTMLレスポンスを得られます。ブログ記事とコメント、商品情報とレビューのように「より重要な」内容と「重要度の低い」内容が明確に分かれる場合に適しています。すべての内容をブロックすれば、実質的に非同期レンダリングを再現したことになります。
5. **`<form>` を活用する。** 最近はちょっとした `<form>` ルネサンスが起きていますが、驚くことではありません。複雑な `POST` や `GET` リクエストを強化しやすい形で扱える `<form>` は、グレースフルデグラデーションの強力な道具です。たとえば[ `<Form/>` の章](../router/20_form.md)の例は、JS／WASMがなくても問題なく動作します。`<form method="GET">` を使って状態をURLへ保持するため、通常のHTTPリクエストを行う純粋なHTMLとして動き、その後クライアント側ナビゲーションを使うよう段階的に強化されます。

まだ見ていないフレームワークの最後の機能が1つあります。フォームのこの特性を基礎に強力なアプリケーションを構築する、`<ActionForm/>` です。
